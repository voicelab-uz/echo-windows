# VoiceLab Echo Windows release verification

Publish the current WinUI 3 x64 source using `BUILD_INSTRUCTIONS.md`, or build `VoiceLab-Echo-Setup-x64.exe` with the installer recipe. Keep portable EXEs beside all published supporting files. Do not treat compilation or startup as an end-to-end pass.

## Automated checks

1. Extract the portable ZIP to a new directory, or install the generated setup EXE. Confirm `VoiceLab.Echo.exe`, `resources.pri`, `Assets/echo-icon.png`, `Assets/QuestionnaireLanguages.json`, `Assets/icons/company-logo.svg`, `Assets/Fonts/manrope-regular.ttf`, `Assets/Fonts/manrope-semibold.ttf`, `Assets/Fonts/OFL.txt`, and `AlphabetLexiconNotices.txt` are present.
2. From this source tree, run `dotnet run --project VoiceLab.WinUI3/VoiceLab.SmokeTests/VoiceLab.SmokeTests.csproj -c Release` on a machine that permits newly built code. It checks local encryption and migration, Mac-compatible auth contracts, note sync and conflicts, STT request behavior, History, usage attribution, notifications, and onboarding APIs.
3. Start `VoiceLab.Echo.exe` from the extracted directory. A first launch must show Welcome with both the Echo icon and VoiceLab company logo. If Windows rejects it, capture the exact Application Control event and stop the runtime test; changing paths or renaming the executable does not establish release readiness.

## Interactive acceptance pass

| Area | Pass condition |
| --- | --- |
| Onboarding | Welcome, permissions, microphone, shortcut, Uzbek alphabet, dictation language, sign-in, six account questions, practice, savings, personalization, and completion all render and navigate. The completion confetti plays without a Composition error, including after navigating back and returning. Restart during questions; answers and position return. On an account whose server questionnaire is already complete, visit the question page, advance to practice, disconnect the network, complete one voice trial, and confirm Finish can use the locally saved server confirmation. Also revisit the question page while offline and confirm that the saved, server-confirmed completion resumes practice; an unsent or other-account draft must not. The first practice page requires one successful, nonempty voice transcription before Continue; later practice pages may be skipped. Leave practice while a slow transcription is pending, then return: that abandoned result must not unlock Continue. Restart at a later practice or completion step before the first successful trial and confirm setup returns to practice. Finish remains unavailable if the account questionnaire is incomplete. After the final question and voice trial have been confirmed, disconnect the network and press Finish: the workspace should open immediately. Restore the network and bring Echo to the foreground or restart; the pending `/v1/desktop/onboarding/completion` request should sync for the same account. |
| Legal links | On Welcome, open Privacy Policy and Terms of Service in the default browser. In Settings, open those plus Refund Policy and Cookie Policy; every link reaches the current VoiceLab page and returns to Echo cleanly. |
| Browser sign-in | Open sign-in and complete it in the browser; Echo should return to the foreground and show the account even if the browser tab closes immediately after callback. During a fresh attempt, send an unrelated request, a duplicate-code query, or a wrong Host header to the local callback port, then complete the valid browser flow; the rejected request must not end the attempt. Leave the sign-in page before completing browser sign-in, return, and start a new attempt; the old callback wait must not hold sign-in for five minutes. Sign out, sign in to a different account, and confirm local History, Notes, and pending audio stay separated. |
| Uzbek alphabet | Choose the new alphabet in setup or Settings. Uzbek dictation inserts forms such as “Özbekiston, ğoya, şahar, çiroyli”; links, code, and English words stay unchanged. Switch back to the current alphabet and confirm the next dictation uses its original spelling. Account History retains the server wording. |
| Microphone | A silent or short test does not unlock Continue. Sustained speech moves the meter and unlocks it. Playback sounds like the captured sample. Disconnect the selected device during a recording; Echo reports a microphone error instead of staying stuck in Recording. |
| Shortcut | Press Win+Alt+Space on its setup page; Continue unlocks. On a PC where Windows rejects registration of this reserved chord, verify the passive keyboard-hook fallback still detects the press and that Setup and Settings warn Windows may also respond. After onboarding, test all three activation modes in Settings while another app has focus: automatic short tap stays hands-free and the next press stops it; automatic hold stops on release; hold mode discards a press shorter than 250 ms and transcribes a longer hold; toggle mode starts and stops on separate presses. If release tracking cannot register, Settings shows toggle-only fallback. An unavailable shortcut reports a clear error and an alternate shortcut works. Changing the shortcut during recording is rejected. Ctrl+Win+V inserts the last transcript when that optional shortcut registers; otherwise the tray's Copy last transcript item remains available. |
| Fast shortcut timing | With native hotkey registration and release tracking available, quickly tap the configured shortcut several times and confirm each physical hold duration is measured from key-down, including a tap released before the UI updates. Automatic mode should keep a short tap hands-free; hold mode should discard taps shorter than 250 ms. |
| Floating control | It stays above other windows, responds to voice level, shows Echo microphone/pause/settings artwork in both themes, stops a recording, opens Settings, and closes with X or Escape without closing Echo. Starting or stopping from the floating control keeps the last external editor as the paste target even after opening Echo Settings. A recording left running reaches the Mac app's ten-minute limit, stops, and transcribes once. |
| Text insertion | Focus Notepad or another editor, dictate a phrase, and confirm the final text appears at the cursor. Also start from Echo's main button, switch to Notepad, and stop with the floating button; the text must reach Notepad. While transcription is still processing, move focus to a second editor; the result should follow the current editor. With automatic paste off, text goes to the clipboard and no keys are sent. Test the keyboard-typing method in an app that rejects paste. Use Ctrl+Win+V in an editor to reinsert the last transcript, then copy it from the tray menu and manually paste it. Check that signing out does not expose the previous account's unsaved last transcript. |
| Failed transcription | Disconnect the network, record a phrase, and confirm Echo shows Retry after the request fails. Reconnect and select Retry; the original audio should transcribe and insert without a new recording. Sign out during a slow request; cancellation should complete promptly and another account must not be able to retry the audio. |
| History | A completed dictation is available after restart. Copy, edit, search, filter, and deletion of a local-only row work, including in a narrow window where the date and actions remain visible and the edit dialog fits. Dictate the same short phrase twice within two minutes; both distinct server IDs must remain visible in History and Home. Account History loads additional pages and preserves server revisions. Disconnect before opening History, then reconnect and use Retry account history without navigating away. The Delete action is disabled for server-backed rows because the desktop API has no account deletion endpoint; Clear device history removes only local copies. Onboarding practice does not add rows. Turn off device History saving in Settings; the next dictation is inserted or copied without a new local row, and account usage attribution still retries after restart. |
| Main pages | Home shows greeting, recent items, and account usage. Edit a transcript on another device, then open Home and confirm the newer account revision appears instead of the stale local text. Narrow Home and confirm the greeting and shortcut hint wrap while the recent-transcripts heading and History button stack without clipping. Statistics shows account activity, savings, streaks, application categories, and the Mac API's desktop/iPhone device split from daily platform rows. Narrow the Statistics window and check the speed and heatmap legends remain inside their cards. Notes, Snippets, Vocabulary, and Upload work with real data. |
| Statistics attribution | Dictate into an external editor while offline, then open Statistics: the application breakdown should show device attribution with a pending-sync note rather than older server totals. Repeat with device History saving off; its encrypted usage outbox should still supply the destination app. Reconnect, let usage sync complete, and reopen Statistics to confirm account totals return. |
| Audio upload | Choose an audio file and transcribe it; copy the result or save it as a note. Choose another file and confirm the old transcript and actions are cleared. Cancel a long upload and confirm the button returns to an idle state. Turn off device History saving, upload another file, and confirm no new local History row is created; the message should state that device History is off. |
| Notes sync | Create and edit offline, restart, reconnect, and confirm upload. Check remote download, pinning, autosave, folders, and a conflict copy after concurrent edits. |
| Layout and theme | Resize to narrow and wide windows, including the dictation language page. The sidebar account row stays on one line; cards and editors remain usable. Onboarding text renders in the bundled Manrope family, including its semibold headings and buttons. Light, dark, and system themes update icons, pages, the recording button, and floating control with visible contrast. |
| Settings | Open Settings on first launch without a resource error. Change shortcut, microphone, Uzbek alphabet, insertion method, and theme; a mistyped saved preference falls back without preventing the page from opening. The microphone privacy button opens Windows Settings. |
| Tray failure recovery | If Windows cannot add or restore the notification-area icon, closing Echo should close the window normally rather than hide it without a way to restore it. After an Explorer restart, verify the icon returns and double-click restores Echo. |
| Startup on a new profile | With no existing `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` key, enable Launch at sign-in, reopen Settings, and confirm it remains enabled. Disable it and confirm no Echo value remains. Test from the final extracted app location. |
| Tray and account | Close to tray, restore, restart Explorer and confirm tray icon returns, change startup setting, then sign out and confirm account data is not shown under another account. Online sign-out should revoke the current server session. Sign in to a new account, reach onboarding practice, and confirm the configured global shortcut starts and finishes its recording before the new workspace opens. Repeat sign-out offline: Echo should remove this device's credential, explain that server revocation could not be confirmed, and allow a fresh sign-in. |

Windows auto-update is not an acceptance item for this review build: no signed Windows release feed or installer manifest exists. The Mac Sparkle feed and older Electron release channel cannot install this WinUI 3 package.

## Current verification status

On November 3, 2026, the PC owner authorized turning off Smart App Control on the development machine. The published app launched, and the per-user installer completed successfully and launched the installed app. Other Windows environments may still block unsigned builds; a trusted signing process is required for a signed distribution.

The application builds with zero warnings and errors. Service smoke tests pass for encrypted persistence and BOM migration, Notes sync/conflicts, STT and authentication contracts, account History, notifications, usage attribution, snippets, statistics, and onboarding APIs.

Selected runtime checks covered the onboarding shortcut-to-practice transition, Vocabulary/Snippets tab switching, History layout, and inline Copy/Copied feedback. A failed dictation was recovered into encrypted History. Full microphone, insertion, account-switching, offline, accessibility, and release acceptance checks above are not all completed.

The default recording mode is toggle: Win+Alt+Space once to start and again to finish. Optional hold and automatic modes remain configurable. The interface is currently primarily English; dictation supports automatic detection plus explicit English, Uzbek, and Russian.

Keep signing credentials and generated build outputs out of the repository. Installer generation and security-policy changes are separate actions; the installer must not turn off Windows protections.
